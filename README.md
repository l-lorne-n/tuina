# 推拿患者次数管理系统

这是一个给推拿门诊本地使用的小系统，用来整理纸质患者卡片、管理患者剩余次数、记录充值/消费流水、保存签名凭证，并按日期、患者和师傅统计经营流水。

项目目前按“本地电脑运行、本地 SQLite 数据库保存”的方式设计。代码可以提交到 GitHub，真实患者数据、签名图片、数据库和密钥都只保存在本机，不进入 Git。

## 当前主要功能

### 患者基础录入

- 从本地 Excel 名单初始化患者。
- 维护患者基础信息：姓名、性别、年龄、电话、体重、身高、地址、备注等。
- 维护原纸质记录中的充值条目。
- 支持患者状态：已录、复核、未录。
- 支持导出当前数据库为 CSV。

入口：

`http://127.0.0.1:8776/`

### 语音辅助录入

- 首页支持录音、调用腾讯云一句话识别、解析录入文本。
- 主要用于整理纸质卡片时快速录入基础信息和原始充值记录。
- 腾讯云密钥文件放在本地，不进入 Git。

### 患者查找

- 支持按姓名、电话、序号搜索。
- 支持卡片视图和签名视图。
- 支持按编号顺序或首字母顺序查看。
- 卡片中展示患者剩余次数、电话和目录/病历/推拿签字图片。
- 患者卡片保留“完整记录”和“增添次数”入口，不再从卡片直接进入电子签名页。

入口：

`http://127.0.0.1:8776/patient-search.html`

### 入口组织

- 患者查找是日常主页面。
- 页面右上角只保留高频主入口：
  - 患者查找
  - 流水总结
- 低频工具统一放在右侧“工具栏”：
  - 后端服务管理：录入页、电子签名
  - 小工具：签名核对、签名测试
- 从患者次数管理页进入工具栏里的“录入页”时，会带上当前患者，直接打开该患者完整记录。
- 从其它页面进入录入页时，按默认逻辑打开第一个未录或第一个患者。

### 次数管理

- 单个患者页面展示基础信息、签名核对、当前剩余次数、次数流水和原录入充值记录。
- 增加次数时可以填写充值次数和充值金额。
- 充值金额不绑定师傅，因为充值是总账收款。
- 减少次数时必须手动选择本次干活师傅。
- 当前师傅选项：
  - 王师傅
  - 杨师傅
- 减少次数后会清空师傅选择，下一次必须重新选择，避免沿用默认值。

入口格式：

`http://127.0.0.1:8776/patient-sessions.html?patientId=患者ID`

### 流水签名

加次、扣次和签名现在是分离逻辑：

1. 点击加次或扣次后，流水先写入数据库，剩余次数立即更新。
2. 签名作为凭证状态，不作为流水生效条件。
3. 未签名流水显示为“待签名”。
4. 后续可以从患者次数管理页或流水总结页补签。

次数管理页提供四个动作：

- 增加并签名
- 增加并待签名
- 减少并签名
- 减少并待签名

“并签名”会在写入流水后跳转到签名页；如果没有保存签名，流水仍然保留为待签名。

### 电子签名

- 支持目录签名、病历签名、推拿签字、流水签名。
- 流水签名会绑定到具体的加次或扣次流水。
- 保存流水签名后，对应流水状态从“待签名”更新为“已签名”。

入口：

`http://127.0.0.1:8776/signature-pad.html`

### 流水总结

- 支持按当天、当月、当年统计。
- 支持筛选单个患者。
- 支持筛选单个师傅。
- 统计内容包括：
  - 充值金额
  - 充值次数
  - 按摩次数
  - 涉及患者数
  - 总流水条数
- 师傅统计只统计消费/扣次流水，充值不归属具体师傅。
- 明细中可以看到待签名/已签名状态，并从待签名流水跳转补签。
- 原录入充值记录会被纳入充值统计，但标记为原记录，不参与流水签名状态。

入口：

`http://127.0.0.1:8776/session-summary.html`

### 签名浏览与核对

- 签名浏览页用于查看从纸质图片切出的目录签名、病历签名、推拿签字。
- 签名核对页用于人工绑定或复核签名图片。
- 这些页面主要服务于前期纸质资料整理和后续核对。

入口：

- `http://127.0.0.1:8776/signature-browser.html`
- `http://127.0.0.1:8776/signature-review.html`
- `http://127.0.0.1:8776/signature-test.html`

## 主要工作流程

### 初始整理纸质资料

1. 把患者名单和签名图片等资料放在本地 `doc_patient/` 中。
2. 启动本地服务。
3. 在首页逐个患者维护基础资料和原始充值记录。
4. 如有需要，使用语音辅助录入，减少手工输入。
5. 在签名浏览/核对页面查看和绑定目录签名、病历签名、推拿签字。

### 日常充值

1. 打开患者查找页。
2. 搜索患者姓名、电话或序号。
3. 点击患者卡片中的“增添次数”。
4. 在患者次数管理页填写增加次数和充值金额。
5. 选择“增加并签名”或“增加并待签名”。
6. 如果现场方便签名，就保存流水签名；如果不方便，后续从待签名流水补签。

### 日常推拿扣次

1. 打开患者查找页。
2. 找到患者并进入“增添次数”。
3. 在患者次数管理页填写减少次数。
4. 手动勾选本次实际干活师傅。
5. 选择“减少并签名”或“减少并待签名”。
6. 系统写入扣次流水并更新剩余次数。

### 后续补签

1. 从患者次数管理页查看“流水签名”区域。
2. 或进入流水总结页，查看明细中的待签名流水。
3. 点击“去签名”。
4. 在签名页保存后，对应流水会变成已签名。

### 对账和查看经营情况

1. 打开流水总结页。
2. 选择统计范围：当天、当月或当年。
3. 可选筛选患者或师傅。
4. 查看充值金额、充值次数、按摩次数、师傅统计和流水明细。

## 本地启动

安装依赖：

```powershell
Set-Location L:\for_mom\tuina
D:\python\python.exe -m pip install -r requirements.txt
```

启动主项目：

```powershell
Set-Location L:\for_mom\tuina
D:\python\python.exe .\server.py --host 127.0.0.1 --port 8776
```

浏览器打开：

`http://127.0.0.1:8776/`

## 测试副本

测试副本通常放在：

`L:\for_mom\tuina_test`

建议使用单独端口启动，避免误连主项目：

```powershell
Set-Location L:\for_mom\tuina_test
D:\python\python.exe .\server.py --host 127.0.0.1 --port 8781
```

测试副本和主项目代码应保持一致，但数据库可以不同。测试副本用于试功能、试流程，避免直接影响主库。

## 数据与隐私

以下内容是本地私人数据，不提交 Git：

- `data/`
- `doc_patient/`
- `history/`
- `.agents/`
- `tecent_api_key.txt`
- `tencent_api_key.txt`
- `.env`
- 日志、缓存和临时文件

代码启动时会自动初始化 SQLite 数据库，并对旧数据库做兼容迁移，例如补充流水、师傅、签名状态等字段。

## 目录结构

```text
.
├── server.py                  # 本地 HTTP 服务和 API
├── requirements.txt           # Python 依赖
├── static/                    # 前端页面、脚本和样式
│   ├── index.html             # 基础录入页
│   ├── patient-search.html    # 患者查找页
│   ├── patient-sessions.html  # 患者次数管理页
│   ├── session-summary.html   # 流水总结页
│   ├── signature-pad.html     # 电子签名页
│   └── signature-*.html       # 签名浏览、核对、测试页面
└── tools/                     # 签名图片切割、预览等辅助脚本
```

本地运行后会使用但不提交的目录：

```text
data/                         # SQLite 数据库和备份
doc_patient/                  # 患者名单、源图片、签名图片等资料
history/                      # 阶段性工作总结
```

## 当前注意事项

- 充值金额不绑定师傅；扣次流水才绑定师傅。
- 加次、扣次一旦确认就会立即更新剩余次数，签名只是凭证状态。
- 如果点了“并签名”但没有保存签名，流水仍然生效，并保持待签名。
- 电子签名已经放入右侧工具栏；日常流水签名应优先从具体流水的“去签名”进入。
- 当前项目面向本地单机使用，暂未做云端部署、账号权限和多终端同步。
